Your Exit A → HKU IDS tour

What is ready, how to check directions, and how to put it online.

← Open the tour

1. Choose how many pictures to see

Above the panorama, use Pictures per walk. Standard has 45 stops. Fewer pictures makes larger steps; Detailed shows all 79 usable pictures. You can change the choice during a walk. Turns, the lift, floor changes and destination junctions stay visible.

Heavily obscured, overexposed and repeated junction pictures have been removed from this website. The original video, GPX and a backup of removed pictures are retained separately. Choosing Detailed does not bring those removed pictures back.

Open the tour

2. Skip or restore an individual picture

  1. Open Configuration console.
  2. Choose Detailed if you want to review every usable picture. Walk through the stops or choose one from the list.
  3. Click Skip this picture below the viewer. The tour moves to the next available picture and connects the arrows automatically. Important turns, junctions and endpoints are protected.
  4. To undo a skip, expand Skipped pictures and click the picture’s Restore button.
  5. Choose your preferred picture density, then click Download settings. Keep this backup, or send it to me. To publish yourself, download route.json and replace that file in the GitHub repository or website hosting. Copy settings is an alternative.

These changes are saved in your browser. Other visitors receive the published version until the updated route.json is uploaded to your hosting. Restore settings loads a downloaded settings file in another browser.

4. Adjust an arrow when needed

  1. Open the direction editor and select the picture to adjust.
  2. Drag the image until the white centre crosshair points at the next path, landing or doorway.
  3. Click Save forward marker here. To adjust the return direction, aim toward the previous stop and click Save back marker here.
  4. Click Use this starting view if you want that opening view saved for this picture.
  5. Download route.json and replace that file on your hosting to publish the changes, or send me your settings file.

Your supplied calibration has already been applied. G/F uses your latest −90° correction, FB/F uses +175°, and P3 uses the individual directions from your saved file. Some markers in that file were still unverified; you can refine them with the same controls.

5. Change section names and arrow appearance

Open Configuration console and choose the section to edit. Expand Section label: two lines, enter the two lines and click Save this section label. No HTML is needed.

Expand Arrow text and rotation, choose Forward or Back, edit its text, adjust the rotation slider and click Save arrow appearance. “Always show this arrow’s text” keeps its label visible without hovering. Rotation turns the symbol; the forward/back marker buttons move it to a different path.

Download route.json to publish these changes through your hosting, or send me the settings file.

6. Add future branches with the same workflow

  1. Start recording a new 360° video at an existing shared junction. Pause briefly so the junction is easy to identify, then walk to the new destination. Keep the 2:1 panorama format.
  2. Give me the anonymized video and GPX, the start/end times, floor names, destination room and the direction to take from the junction. Indoors, also provide a floor plan or landmark descriptions if available.
  3. I extract the new pictures, remove repeats and obstructed views, and connect the route to the existing junction. Shared corridor pictures can be reused.
  4. You visually check any new directions in the editor and send back the downloaded settings.
  5. I apply the settings and update the same website. The destination’s “Coming soon” choice becomes an active route.

You can add more destinations and station entrances this way without rebuilding the whole tour. The indoor overview currently shows walking order, rather than a measured floor plan.

7. Hide the device holder at the bottom

The panorama is limited to a lower viewing edge of −55°, with a slightly downward starting view. In the console, expand Hide the bottom / device holder, change the slider and save. Markers below this limit display inside the visible area so you can still walk.

A viewing limit affects the player only. For a public tour, use pictures with the holder area permanently covered. Keep any unredacted originals in private storage. The cover follows the device holder, with a small cap at the very bottom, so surrounding floor remains visible. It does not remove faces elsewhere in the scene; those need their own check before public upload.

8. WordPress pictures + GitHub Pages tour

  1. Review the prepared picture batch before public upload. In WordPress, use Media → Add New Media File and upload the individual JPGs from the batch, together.
  2. Open one picture’s attachment details and copy its File URL. For a “-scaled.jpg” copy, use the original full-size file address. A cropped thumbnail will not work as a 360° picture.
  3. Open the Configuration console. Expand WordPress picture addresses, paste one original JPG URL from the batch and click Apply this folder to all pictures. The batch must keep its filenames and be uploaded into one folder/month. Fix any renamed files using their individual URLs.
  4. The WordPress host must allow the tour to load its pictures. If a picture works directly but the tour reports an error, ask the web administrator to allow the tour’s origin in the image server’s CORS response header, or host the tour on the same WordPress origin.
  5. Create a public GitHub repository named hku-ids-tour. Upload only the contents of the software package. The pictures remain on WordPress.
  6. Download route.json to publish from the console and replace route.json in GitHub. Commit the update.
  7. In the repository, open Settings → Pages. Select Deploy from a branch, then main and /(root), and save. GitHub shows the public website address when the deployment is ready.
  8. Open the Elementor block generator, enter that public website address, copy the block, and paste it into an HTML widget on your Elementor page. Update the page and check it in a private/incognito window.

The console previews and downloads your configuration. It has no server-side Publish button. Only an authenticated GitHub/hosting editor can change the live tour. Future branch updates replace the configuration and add their pictures; the WordPress embed address stays the same.

Our JPGs are 4096 × 2048. WordPress normally creates a smaller copy above 2560 pixels; use the original upload. Your WordPress administrator can help if the original address is not shown.

9. Host everything on an HKU web server instead

The portable package contains the tour software and its pictures. Give it to your web administrator to host together. This avoids cross-site image loading and can support an authenticated administration console later. Embed that public tour address with the same Elementor block generator.

Pannellum runs from a local copy included with the tour. No Pano Mapper subscription or external viewer CDN is required for this version.
