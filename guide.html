Open visitor tour

One shared tour, updated through GitHub

Use the configuration console to preview edits. Publish its full route.json through the GitHub repository. The panoramas stay in WordPress’s Panorama media folder. You do not need to send a settings file to the assistant for routine changes.

1. Edit and publish, step by step

  1. Open the console. Choose a Destination / route and a stop. Adjust your labels, picture pace, markers or junction guidance.
  2. Check the result in the panorama. Changes are saved in this browser as a Local preview.
  3. Click Download route.json to publish. Keep the filename route.json.
  4. While signed into GitHub, open hkuids / hku-ids-tour. At the repository’s main file list, choose Add file → Upload files. Select the downloaded route.json, then click Commit changes.
  5. Open the repository’s Actions tab. Wait for the newest pages build and deployment to show success.
  6. Open the visitor tour and click Reload tour. The Published date below the walking buttons identifies the configuration now loaded. Reload the WordPress page containing the embed as well.

An already-open page keeps the version it loaded. The console can also contain unpublished browser edits. GitHub is the shared configuration; the console does not automatically write to GitHub. Only a signed-in repository editor can publish.

Download optional settings backup preserves your edits for restoring in another browser. It is optional and should not replace the full route.json. If GitHub has changed since you opened the console, the publish download asks you to back up, reset to the published tour and restore your edits first, so you cannot accidentally overwrite newly added routes.

2. Change pictures and section names

Choose Standard, Fewer pictures or Detailed under Pictures per walk. To remove an ordinary stop, click Skip this picture. Restore it under Skipped pictures. Junctions, lift stops, important turns and endpoints stay available at every pace.

For labels, choose a section and expand Section label: two lines. Type the two lines separately, then click Save this section label. No HTML is needed.

The redundant card after the P2 junction and the old P2–P3 stairs pictures have been retired. The next stop after P2 is the P3 junction. Your earlier skipped pictures, including the blurred s2-030, remain skipped.

3. Move, rotate and label each marker

  1. Open a junction or any other stop in the console.
  2. Expand Place / rotate any arrow or information marker. Under Which marker?, select the exact forward, back, branch or information marker. The view turns toward it.
  3. Drag the panorama until the desired path or doorway sits beneath the crosshair. Click Place selected marker at crosshair.
  4. Change Marker text, Arrow rotation and whether its text always appears. Information icons also have an editable Information link. Click Save marker appearance.
  5. Publish route.json using the steps above.

Rotation turns the arrow symbol. Placement moves it within the panorama. Setting a choice’s “Left / Right / Downstairs” label does not automatically move its arrow. To change the initial viewing direction, aim the panorama and click Use this starting view.

The additional indoor markers are starting estimates from the recording. Tune each marker visually; indoor GPS and compass bearings drift.

5. Add another branch

  1. Record a 2:1 panorama video from a known junction to the destination. A reverse recording also works if you identify its direction.
  2. Provide the video, start junction, room name/link, floor changes and lift button instructions. Include GPX if available; indoors it is optional. Mention pauses, blurred sections and preferred junction frames.
  3. The preparation workflow selects spaced frames, removes duplicates and waiting footage, obscures people and the device holder, then uploads the prepared JPGs to WordPress’s Panorama folder.
  4. The new route is connected to the existing junction in route.json and published. You then tune its markers and starting views through the same console.

The console currently edits prepared routes; it does not turn an uploaded MP4 into a branch automatically. More routes can be added without changing your WordPress embed. The indoor map shows walking order, not a measured floor plan.

6. Pictures, privacy and WordPress

The new P603 batch contains 25 JPGs at 2560 × 1280, about 7.7 MB in total. Original videos and unmasked review pictures stay local. Use the prepared WordPress originals, avoiding smaller “-scaled” copies. Already-published images are accessible by their direct URL, so permanently covering a person/device in the image is what protects that content.

The viewer defaults slightly downward and permits looking down to the configured edge. Expand Hide the bottom / device holder to tune that edge. Changing it does not redact the original JPG.

For a later batch in another upload month, update only the relevant pictures’ URLs. Apply this folder to all pictures replaces every address and should only be used when the whole tour’s images share that folder.

Open the Elementor block generator, copy its iframe into an Elementor HTML widget, then publish/update your page. Future tour changes use the same embed URL.
