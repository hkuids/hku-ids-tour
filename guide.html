← Visitor tour

One tour. One shared configuration.

Panoramas are hosted in WordPress’s Panorama media folder. GitHub’s route.json controls the shared tour. The configuration console saves a local preview until you publish.

Move through the panorama

Drag or swipe to look. Click an arrow to walk. Double-click or double-tap a clear area to walk toward the nearest facing arrow. Arrow keys look around; Shift + ↑ walks in the facing direction and Shift + ↓ goes back. Enter also walks when the panorama has keyboard focus.

Open the small menu for destination, pace, sections and stops. Lift cards have a lift button: press FB at Main Campus, P6 at the Graduate House P2 lift, or P2 when returning from P6.

Edit on any device

  1. Open the console. Use the menu to choose a route and stop.
  2. Use Show / hide & presentation for whole-tour defaults or an individual scene. Hide location labels, cards, descriptions, arrows, room info, progress or navigation controls.
  3. Select an individual marker to move it with the crosshair, rotate it, choose its arrow style/symbol, hide its icon or show its label. Hidden markers remain selectable in the console.
  4. At a junction, edit each destination card and its status visibility. At a lift, edit the card wording. Section labels have two separate text fields.
  5. Export route.json before switching devices. On the other device, use Import route.json or settings backup. A full export includes routes, pictures, placement, presentation and viewing limits.

Indoor viewing limits can be set per scene. The current indoor default is −65°. Permanent covers still protect the device holder in the JPG itself; lowering the viewing limit cannot undo those covers.

Publish your final configuration

  1. Click Export & open GitHub. Keep the downloaded filename route.json.
  2. In the GitHub upload page, choose the downloaded file and click Commit changes.
  3. Wait for the newest Pages deployment to succeed, then reload the visitor page and WordPress embed.

Finalised configuration must be uploaded to GitHub and committed. The button exports the file and opens GitHub; it does not commit automatically. GitHub Pages hosts a static site. An automatic commit service would need a separately configured authenticated backend. No GitHub token is stored in the public tour.

The published date is in the options drawer. An open page keeps the version it loaded. The console refuses an export if GitHub has changed since you opened it: export a settings backup, reset to the published tour, import the backup and check the result before publishing.

Rooms and future branches

Only a reached room has a room-information icon. Unrecorded routes at junctions say Coming soon. The existing P307, P603 stairs and P603 lift routes are available.

To prepare another branch, provide its video, start junction, destination, floor changes and lift instructions. GPX is optional indoors. The preparation workflow selects spaced frames, removes pauses/duplicates, covers people and the holder, uploads prepared JPGs to WordPress and connects the branch in route.json. You then tune it in the same console. The WordPress embed address stays the same.

WordPress embed

Use the Elementor block generator. Place its iframe in a full-width HTML widget. The panorama fills the iframe; the fullscreen button expands it when the browser allows fullscreen. Uploading pictures alone does not create a linked branch.
